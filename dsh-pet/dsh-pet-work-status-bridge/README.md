# dsh-pet-work-status-bridge

独立的 DeepSeek Harness 插件。它监听 DSH 的会话事件，分别记录活跃会话和并行 Agent 的工作状态，并把状态列表写入 `$DSH_HOME/dsh-pet/work-status-bridge.json`，供 DSH Pet 独立版读取。桌宠宿主将所有 DSH 会话和 Agent 汇总为一个 DSH 客户端状态，因此 DSH 同一时间最多占用一只桌宠。当前选中的主对话仍用于决定系统通知的来源；在 DSH 页面失焦时，插件可转发该对话的完成、失败、权限申请和待回答问题通知。

## 多 Agent 分配

- DSH 开始工作时，宿主从已启用「工作状态联动」的空闲桌宠中动态挑选一只；工作期间保持分配，回到空闲后释放，下次工作可分配到另一只。
- 多个不同客户端同时工作时各自占用不同的空闲桌宠；桌宠不足时，未分配的客户端等待空位释放。
- 插件仍按会话和 Agent 发布状态；桌宠宿主负责合并成单个 DSH 客户端状态。成功或错误状态保留 60 秒，以便播放结束动画；中断状态会立即清除。若 DSH 没有发出结束事件，活动状态最多保留两小时，避免把长时间运行的任务误判为空闲。
- Agent 标识只以哈希形式写入桥接文件，不保存原始会话 ID。状态文件不包含提示词、对话正文、工具参数或工作区路径。

## 通知与多来源限制

客户端每两秒报告当前选中的会话 ID 与窗口焦点状态，并在焦点变化时立即报告。该选择只用于系统通知：子代理和委派会话不会单独产生通知。通知标题和正文（例如问题内容或权限原因）会临时写入桥接文件，供独立版跨进程读取，最多保留 15 秒；不会保存会话历史。独立版的通知受「系统通知」总开关控制，并且桌宠窗口也必须处于失焦状态。

独立版同时检测 DSH、Codex 和 Claude Code 桥接文件，并为每个客户端来源分别维护一个工作状态。不同客户端可同时占用不同桌宠；同一客户端的多个会话和 Agent 会先合并，不会额外占用桌宠。

## 本地安装

在 DSH 使用的 PowerShell 终端里，把路径替换为本仓库中此目录的绝对路径：

```powershell
dsh plugin --profile desktop add "D:\path\to\dsh-pet\dsh-pet-work-status-bridge"
```

如果桌面使用的 profile 名称不是 `desktop`，将其替换为实际 profile。此桥接插件版本为 `0.2.0`。安装或更新后重启 DSH；启动独立版后，启用桌宠配置里的「工作状态联动」即可。

卸载：

```powershell
dsh plugin --profile desktop remove dsh-pet-work-status-bridge
```

此目录是独立 bundle，安装和卸载都不要求安装或卸载 DSH 的 `dsh-pet` 插件。
